# 004 — Student access and accounts (PR #62)

Issues: #25 Google sign-in/sign-out · #26 token verification and per-student scoping · #46 account deletion (parent epic #4). History before 2026-11-20: `docs/implementation/issue-4.md`.

## Outcome
A student signs in with Google only, reaches the protected practice shell from #17, signs out, and can request account deletion with explicit confirmation. Nobody unauthenticated reaches a protected screen, and no student can read another student's data.

## Requirements
1. R1: The branch includes the merged #71 scaffold. Its structure is preserved: `app.json`, Jest tests, `library/` routes, `PreviewScreen`, and tab styling. Account work is layered on top without replacing it.
2. R2: `Stack.Protected` guards keep Welcome and Sign-in public and every `(student)` route protected (#25).
3. R3: Google is the only sign-in method shown. It uses Google Identity Services on web and the native Google Sign-In module on Android and iOS (#25).
4. R4: Sign-out clears the stored session, and protected routes become unreachable afterwards (#25).
5. R5: The Account screen offers deletion behind an explicit confirmation. After the request, the student is signed out (#46).
6. R6: Tokens never appear in logs or in committed configuration. Only public client IDs go in the bundle environment (#25).
7. R7: One test runner (Jest, `jest-expo`) and one lockfile generated by CI's npm 11.19.1. Student CI is green.

## Acceptance criteria (this cycle)
- [ ] #25: real Google sign-in reaches the protected Library on web and Android. iOS proof moved to #103.
- [ ] #25: sign-out makes protected screens unreachable; unauthenticated deep links redirect to Sign-in.
- [ ] #25: no other sign-in method appears; tokens are never logged.
- [ ] #46: after a deletion request the student is signed out and deleted scores can't be retrieved.
- [x] #26 criteria were proven before this cycle (see `docs/implementation/issue-4.md`). Re-run the tests after the merge.

## Non-goals
iOS device or simulator proof (#103), GCP foundation (#18 / PR #99), notification destinations, and auth abuse controls. Those last two are launch gates tracked separately, not merge gates for #62.
